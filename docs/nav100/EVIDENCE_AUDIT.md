## 3. Checkpoint and completion truth

A central NAV100 risk is promising “Continue” where the current runtime only remembers learning outcomes, not interaction position. The actual baseline is heterogeneous:

| Experience/state | What persists today | What does **not** persist today |
| --- | --- | --- |
| Story reading | Story ID, exact beat ID, completed flag, favourite | Nothing in this audit changes that contract. |
| Learning Studio | Activity-scoped workspace with activity/question revision/engine binding | It is not mastery and must not be treated as a completed learning outcome. |
| Structured long mock | Session checkpoint, question/section signatures, exact state validated before resume | Only `goal_pattern_mock` is wired to App checkpoint persistence. |
| Free question sessions generally | Attempts/mastery evidence after submissions | No generic exact current-question/session resume in inspected App flow. |
| Bicycle guided workshop | Child can reopen the workshop; practice evidence persists when submitted | Guided section/idea (`part`/`idea`) is component-local and not persisted. |
| Sound Trail | Attempts persist; completed recognition attempts can re-project the Sound Trail discovery | Current sound/stage position and `finished` UI state are component-local. |
| Learn About | Attempts from evaluated nested questions persist; studio work persists inside studios | Selected topic/depth/section browsing position is not persisted as a universal resume checkpoint. |
| World-action mission | Completed mission and replay-deduping session IDs persist | Partial step/drag/assembly position is local to the practical viewport and is not a durable world-action checkpoint. |

Consequently, a future home can safely say **Continue** only for experience types whose current checkpoint owner supports that claim, or after G1 explicitly defines a truthful weaker reopen label (for example “Open again” or “Keep playing” where exact position cannot be restored).

## 5. Findings that constrain NAV100-02 and later work

1. **There is no existing general authored-experience discovery registry.** A later adapter may project references from current owners, but must not become a second content database.
2. **“Knowledge Journey” is not a current repository surface/ID.** The existing topic product is Learn About (`learn.*`). G1 must decide whether to rename/present it differently; #285 cannot silently equate the two.
3. **“Scientu's Lab” currently exists as story-world location ID `scientu-lab`.** That does not by itself establish a broad Lab taxonomy for every manipulable model.
4. **Learning Studios already solve canonical activity identity and contextual reuse.** Their activity IDs (`studio.*`) are the identity; topic/workshop bindings are placements. NAV100 should not clone a studio for each entrance.
5. **Resume support is type-specific, not universal.** Stories, studios, and long mocks have different persistence owners. Bicycle guided navigation, Sound Trail position, Learn About browsing position, and incomplete world-action steps do not have equivalent durable checkpoints.
6. **Question engines, experience recipes, studios, authored experiences, and discovery projections are different layers.** Treating them as one “game type” list would lose authority/evidence semantics.
7. **Session-limit policy exists but live launch integration was not established by inspected source.** Any NAV100 acceptance test about session limits must first identify the actual integration point rather than assume the isolated policy is enforced globally.
8. **Physical investigation is a real capability gap.** Direct manipulation/world-action screens can represent digital work but cannot certify real-world touch, temperature, bounce, or observation.
9. **Primary stories are a first-class experience, not a quiz prelude.** Existing story manifests explicitly disallow mastery writes and have exact reading resume.
10. **Phonics audio approval is granular.** Sound Trail marks `/f/` and `/s/` candidates pending human review even though bundled files are present; presence of an asset is not editorial/audio approval.
